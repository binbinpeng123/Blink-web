# 已知限制

本文件列出第一版（v0.1）明确不承诺的能力与运行前提。未列出的行为不应被推断为
已支持；性能数字的适用范围见 [testing.md](./testing.md)。

## 1. 默认经同源代理，不能假定任意端点可直连

- 本前端以同源代理为唯一部署形态，静态页面必须与代理同源部署；不能只把
  `dist/` 放到 CDN 上就使用。
- Blink v0.1 不返回 CORS 头；后端 `feature/cors` 切片已实现桶级
  `PUT`/`GET`/`DELETE ?cors` 与 `OPTIONS` 预检。要直连该版本，必须先升级后端、
  在桶上写入匹配前端源的规则，且前端 UI 目前不提供 CORS 配置编辑——因此直连
  不作为本版的部署形态。
- 其他任意 S3 端点能否直连取决于其自身 CORS 配置，本前端不做探测。
- **回环模式免鉴权**：默认只监听 `127.0.0.1`，能访问该端口的人就能以代理身份访问
  后端。该模式只用于本机调试，不能直接暴露到公网。
- **公网模式**：设置 `BLINK_WEB_TOKEN` 后启用登录页与会话 Cookie，静态资源与
  `/s3` 全部受保护；没有令牌时监听非回环地址会拒绝启动。这是单一共享口令，不是
  多用户账号体系：不区分用户、没有审计记录，拿到令牌即有完整代理访问权（仍需
  自行提供 S3 凭据才能签名）。
- **登录失败限速**：同一来源 60 秒内失败 5 次后暂停 30 秒，连续触发每次翻倍，
  上限 5 分钟；暂停期返回 `429` + `Retry-After`。限速状态只在内存里，重启即清空。
  经隧道 / 反向代理部署时必须设置 `BLINK_TRUST_PROXY=1`，否则所有访问者对服务
  来说都是 `127.0.0.1`，会共用同一个限速桶——一个人试错会把所有人一起锁住。
  反过来，服务直接监听公网时**不要**开启该开关：那时任何人都能伪造
  `CF-Connecting-IP` 来无限拿到新配额。
- 会话 Cookie 是无状态 HMAC（有效期默认 24 小时），登出只清除浏览器 Cookie；
  要立即吊销已泄露的会话，必须轮换 `BLINK_WEB_TOKEN` 并重启服务。
- 服务端不内置 TLS。公网必须由 Cloudflare 隧道、反向代理或其他 TLS 终结层提供
  HTTPS，并保留原始 `Host`；明文 HTTP 下令牌和 S3 凭据都可被窃听。
- Cloudflare 临时隧道的域名每次启动都会变化，本机休眠或断网即失效；隧道运营方
  在边缘终止 TLS，可见流量元数据。它适合临时演示，不作为生产可用性承诺。
- 公网链路的吞吐由「浏览器 → 隧道边缘 → 本机 → 后端」全程决定，与后端能力无关。
  实测经隧道 + 逐连接 SSH 中继上传/下载 12 MiB 仅约 0.3 MiB/s（见
  `docs/testing.md` 第 10 节），只可用于功能验证，不能用于性能评估。
- 反向代理必须保留浏览器原始 `Host`。重写 `Host`（或把路径前缀改成后端不认识的
  形式）会让浏览器签名与后端校验不一致，表现为 `403 SignatureDoesNotMatch`。
- `BLINK_ENDPOINT` 只允许端口级地址（`http(s)://host[:port]`），不能带路径、查询
  或片段；这是为了避免代理变成可配置的开放转发器。

## 2. 对象 key 的限制

- key 中不能出现空段、`.` 段或 `..` 段。浏览器 URL 规范会折叠这些段，Go
  `ServeMux` 也会对 `//`、`/./`、`/../` 返回 307；客户端和代理都会显式拒绝，
  而不是发出一个签名路径与后端路径不一致的请求。
- 以 `/` 结尾的目录占位对象可以浏览和删除，但前端不会为它生成"目录下载"。
- 其他 S3 实现若允许上述 key，本前端仍无法操作它们。

## 3. 浏览器连接与并发

- 浏览器对同一源通常只开约 6 个 HTTP/1.1 连接。上传/下载共享全局
  `Semaphore(4)`，压测面板也受此上限约束。
- 因浏览器面板的并发与吞吐受连接池限制，**不能用面板数字代表服务端吞吐**；
  权威压测请使用 `npm run bench`。
- 同一浏览器标签页内的上传、下载、压测会竞争这 4 个传输名额；多标签页之间没有
  协调机制。

## 4. 凭据与传输安全

- secret 只保存在内存中，刷新页面即丢失；可选的 sessionStorage 只保存 access
  key 与 region，且默认关闭。secret 在任何情况下都不写入 sessionStorage /
  localStorage。
- 明文 HTTP 下，凭据、对象内容和签名头都可能被同网段窃听。只建议在 localhost
  使用，或置于 TLS 终止之后。
- 公网入口的访问令牌保护的是 Web 控制台与代理入口，不改变"签名在浏览器完成"的
  模型：任何通过门禁的访问者仍需输入自己的 access key / secret，服务端不保存、
  不转发这些凭据。
- 代理日志不记录请求头（包括 Cookie 与 `Authorization`），但反向代理 / 隧道 /
  后端自己的日志策略不在本项目控制范围内。
- 开启 `BLINK_TRUST_PROXY=1` 后，`CF-Connecting-IP` / `X-Forwarded-For` 会被用于
  日志与限速。这些头由代理填写，服务端无法验证其真实性；只有在对端确实是自己
  的隧道 / 反向代理时才可开启。日志只写地址，不写整条请求头。
- 浏览器端签名依赖安全上下文（`crypto.subtle`）；非 HTTPS 且非 localhost 的
  页面会在启动时被拒绝。

## 5. 下载完整性

- 下载器逐块核对实际字节数，并带 `If-Match` 防止对象在下载过程中被替换；它
  **不**在浏览器内计算整文件 SHA-256。端到端哈希一致性由
  `npm run test:integration` / `npm run test:e2e` 的测试代码验证，不是 UI 的
  运行时保证。
- 分片上传的 SHA-256 是 COMPOSITE（`x-amz-checksum-type: COMPOSITE`），等于
  各分片摘要的合成值，**不等于** `shasum -a 256` 的整文件结果。界面会显示
  `COMPOSITE` 并给出说明，不会把它标成整文件哈希。
- HTTP 层只能保证"收到的字节数正确 + ETag 未变"；要证明内容未被中间人替换，
  需要 TLS 或应用层额外校验。

## 6. 下载落点

- File System Access API 目前只有 Chromium 系浏览器支持（本次只验证 Chrome
  155）。Safari / Firefox 会自动回退到内存 `Blob`。
- 内存回退上限为 256 MiB；超过上限直接拒绝，避免标签页 OOM。大文件在非
  Chromium 浏览器上不可下载。
- File System Access 的保存对话框需要用户手势；环境中没有该 API（Safari /
  Firefox）或被拒绝时回退内存 Blob，用户主动关闭对话框则按取消处理。
- 系统保存对话框可能出现在浏览器窗口之后；点击下载后请看任务行的
  「等待系统保存对话框…」提示，不要重复点击下载。
- 不提供跨会话断点续传；刷新或关闭页面后，未完成的上传/下载需要重新开始。

## 7. 不支持的对象能力

以下能力在 Blink 当前版本中未实现或返回 `501`，前端不提供入口：

- ACL、Bucket Policy、版本控制、对象标签、批量删除；
- 预签名 URL、分享链接、对象预览；
- 跨桶复制 / 移动、生命周期规则、事件通知；
- 多端点、多租户、跨区域复制。

## 8. 压测限制

- 压测是**同机自环**：客户端与 Blink 争抢同一台机器的 CPU、内存和磁盘，结果只
  作为本机回归基线，不是对外性能承诺，也不代表真实边端设备或网络条件。
- CLI 默认 `--fsync-policy always`；换成 `meta` 会得到不同量级的写入数字，不能
  混在同一张表里比较。
- 每个尺寸最多跑 `--target-samples` 个样本，同时受 `--duration` 与写入预算限制；
  被截断的用例会标 `budgetLimited`，其样本数少于目标值。
- 浏览器面板默认总写入预算 256 MiB；CLI 默认总预算 512 MiB，按尺寸均分
  （`--sizes` 有 4 个尺寸时每个 128 MiB）。预算用于保护磁盘，不是服务端配额。
- 样本量小、运行时间短的数字波动很大；不要把单次 p99 当作稳定 SLA。
- CLI 的 `--spawn` 模式会为每个尺寸启动独立临时后端，其数据目录、页缓存与正式
  部署不同；结果适合做版本间回归，不适合直接外推容量。

## 9. 单机与边端扩展

- 当前只支持一个 `BLINK_ENDPOINT`，没有节点发现、桶到节点的映射、跨节点 GC
  协调或离线队列。
- `HttpTransport` 是预留的扩展点，但"可以替换传输层"不等于分布式能力已经实现；
  多节点一致性、故障转移和冲突解决都不在本版本范围内。
- 单机 Blink 的容量、可用性与数据持久性由后端自身保证，前端不增加副本或重试
  之外的保护。

## 10. 兼容性与验证范围

- 本次只在 macOS 15.7.9 / Apple M4 / Chrome 155 / Node 24.18.0 上验证。
- 未在 Safari、Firefox、移动端浏览器、Windows、Linux 或真实边端设备上做完整
  回归。
- 前端依赖 Blink 的这些行为：HEAD/GET 仅在 `x-amz-checksum-mode: ENABLED` 时
  返回校验和、MPU 校验和为 COMPOSITE、`DeleteObject` 只删元数据并把块留给 GC。
  换用其他 S3 实现时，校验和与删除语义可能不同。
- 没有 i18n、无障碍专项审计（仅做了基本的语义标签与键盘关闭弹窗）、主题切换或
  离线模式。
